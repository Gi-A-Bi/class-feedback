# 발표 평가 프로그램

초등학교 수업에서 학생들이 친구의 발표를 듣고 평가하는 웹 프로그램입니다.
기획 내용은 [CLAUDE.md](./CLAUDE.md)에 있습니다.

개발 순서 1~6단계를 모두 마친 상태입니다.

| 누가 | 주소 |
| --- | --- |
| 학생 (태블릿) | 그냥 주소만 — 예: `무엇무엇.vercel.app` |
| 선생님 (PC) | 주소 뒤에 **`/teacher`** — 예: `무엇무엇.vercel.app/teacher` |

학생이 주소만 치면 바로 입장 화면이 나오도록 해 뒀습니다.
선생님 화면은 `/teacher` 를 붙여서 들어가시고, **즐겨찾기에 넣어 두시면 편합니다.**

---

## 수업에서 쓰는 순서

1. **선생님**: `/teacher` 에서 학급을 열고 **활동 만들기** (제목, 평가 기준, 발표 순서)
2. **선생님**: 활동 화면에서 **발표 시작하기**
3. **학생**: 태블릿에서 주소를 열고 **칠판에 적어 둔 입장 코드**를 넣은 뒤 자기 이름을 고릅니다
4. 학생 화면에 지금 발표자가 뜨고, 별점과 코멘트를 적어 냅니다
   - **발표자 본인**에게는 노란 바탕의 **자기 평가** 화면이 나옵니다
5. **선생님**: 제출 인원을 보면서 **다음 발표자 →** 를 누릅니다
   - 누르는 순간 학생 화면이 저절로 넘어갑니다. 학생은 활동을 끝내기 전까지 "지난 평가"에서 앞 발표의 평가를 고칠 수 있습니다
6. 마지막 발표까지 끝나면 **활동 끝내기**

### 누적 기록과 엑셀

학급 화면의 **누적 기록 · 엑셀** 버튼으로 들어갑니다. 선생님만 보는 화면입니다.

- 끝난 활동마다 학생이 친구들에게 받은 별점 평균이 표로 나옵니다
- 이름을 누르면 그 학생의 회차별 기록(기준별 친구들 평균과 자기 평가, 변화 그래프)이 나옵니다
- **엑셀로 내려받기**: "한눈에"(학생 × 활동)와 "기준별"(학생-활동-기준마다 한 줄) 두 시트
- 활동 하나의 자세한 내용은 그 활동의 **결과 보기** 화면에 있는 **엑셀로 내려받기**로 받습니다.
  "요약"과 "평가 전체" 두 시트이고, 평가한 학생의 이름과 코멘트가 들어 있습니다

활동은 **활동 끝내기**를 눌러야 누적 기록에 들어옵니다. 이 기능이 생기기 전에 끝낸 활동은
누적 기록 화면에 "기록에 넣기" 안내가 뜨니 한 번 눌러 주세요.

### 기준 묶음

활동 만들기 화면의 "평가 기준" 아래에서, 지금 기준에 이름을 붙여 저장해 두고 다음 활동에서
**불러오기**로 한 번에 넣을 수 있습니다.

### 모둠 발표

활동을 만들 때 맨 위에서 **모둠 발표**를 고릅니다.

1. **모둠 수**를 적고 **번호순으로 나누기** 또는 **무작위로 나누기**를 누릅니다
2. 손으로 고치려면: 모둠 칸을 눌러 고른 뒤, 위쪽 "모둠이 없는 학생"에서 이름을 누르면 그 모둠에
   들어갑니다. 모둠 안의 이름을 누르면 빠집니다
3. 모둠 이름은 칸에 바로 고쳐 적습니다 (예: 해바라기)
4. 전에 했던 모둠 활동이 있으면 **이전 활동의 모둠 불러오기**로 같은 편성을 다시 쓸 수 있습니다

수업 중에는 이렇게 됩니다.

- 다른 모둠 학생들은 **모둠 전체를 한 번** 평가합니다
- 발표하는 모둠의 모둠원은 **각자** 자기 평가를 합니다
- 결과를 공개하면 모둠원 모두에게 같은 평균 별점과 코멘트가 가고, 자기 평가는 각자 쓴 것만 보입니다
- "내 기록"에는 **모둠** 표시가 붙어 개인 발표와 구분됩니다
- 모둠에 넣지 않은 학생은 발표 없이 평가만 합니다

### 발표 순서 바꾸기

순서는 활동을 만들 때뿐 아니라 **만든 뒤에도, 수업 중에도** 진행 화면 오른쪽 "발표 순서"에서 바꿀 수 있습니다.

- **화살표**: 한 칸씩 앞뒤로 옮깁니다
- **이름 누르기**(수업 중): 그 학생의 발표로 바로 넘어갑니다
- **무작위로 섞기**: 시작 전에는 전체를, 수업 중에는 지금 발표 뒤의 순서만 섞습니다

### 결과 살펴보고 공개하기

1. 진행 화면이나 학급 화면에서 **결과 보기**를 누릅니다
2. 발표자마다 친구들이 준 평균 별점과, **누가 어떤 평가를 했는지**가 이름과 함께 보입니다
3. 친구에게 보이면 안 되는 코멘트는 **숨기기**를 누릅니다. 숨겨도 점수는 평균에 들어갑니다
4. **결과 공개**를 누르면 학생들이 태블릿의 **내 기록**에서 자기 결과를 봅니다
   - 학생에게는 **이름 없이** 평균 별점과 코멘트만 나가고, 코멘트 순서도 섞여 나갑니다
   - 학생은 자기 것만 봅니다. 다른 친구의 점수나 순위는 어디에도 나오지 않습니다
5. **공개 취소**를 누르면 학생 화면에서 사라집니다. 평가는 지워지지 않으니 다시 공개할 수 있습니다

공개한 뒤에 숨김을 바꾸면 학생에게 보이는 결과에도 바로 반영됩니다. 공개한 뒤에 새로 들어온
평가는 결과 화면의 **공개 내용 새로 고침**을 눌러야 반영됩니다.

### 학생이 이름을 잘못 골랐을 때

한 번 고른 이름은 다른 태블릿에서 다시 고를 수 없게 잠깁니다. 풀어 주는 방법은 두 가지입니다.

- **수업 중**: 진행 화면의 학생 칸(예: `2 이바다`)을 누르면 그 학생의 기기 연결이 풀립니다.
  그 태블릿은 입장 화면으로 돌아가고, 이름을 다시 고를 수 있습니다.
- **수업 전**: 학급 화면의 "지금 명단"에서 한 명씩 **풀기**, 또는 **기기 연결 모두 풀기**.
  태블릿을 여러 반이 돌려 쓴다면 수업을 시작하기 전에 한 번 눌러 두면 깔끔합니다.

진행 화면에서 점선으로 된 흐린 칸은 아직 들어오지 않은 학생입니다.

### 혼자 미리 해 보기

선생님 PC 한 대로도 됩니다. `/teacher` 에서 발표를 시작한 뒤, **새 탭**에서 학생 주소를 열어
입장 코드를 넣고 아무 이름이나 골라 평가를 내 보세요. 다 해 본 뒤에는 학생 화면의 **나가기**를
누르거나 위의 방법으로 기기 연결을 풀어 두세요.

## 2단계에서 선생님이 하실 일

1단계 설정(아래 A~G)을 이미 마치셨다면, 추가로 하실 일은 **보안 규칙 올리기** 하나뿐입니다.
`firestore.rules` 파일의 내용을 Firebase 콘솔에 붙여넣으면 됩니다.

1. Firebase 콘솔 → **빌드(Build) → Firestore Database → 규칙(Rules)** 탭
2. 글상자 안의 내용을 **전부 지우고**, 이 저장소의 `firestore.rules` 파일 내용을 그대로 붙여넣습니다
3. **게시(Publish)** 를 누릅니다

이걸 해야 학급을 만들고 명단을 저장할 수 있습니다. 안 하면 "학급을 만들지 못했어요"가 뜹니다.

> **규칙은 단계마다 바뀝니다.** 6단계에서 누적 기록과 기준 묶음 규칙이 더해졌으니,
> 전에 올리셨더라도 **다시 올려 주셔야** 누적 기록을 보고 기준 묶음을 저장할 수 있습니다.

### 2단계에서 쓸 수 있는 것

- 구글 계정으로 로그인 / 나가기
- 학급 만들기 (입장 코드가 자동으로 생깁니다)
- 학급 이름 고치기, 학급 지우기
- 명단 붙여넣기 일괄 등록 — 엑셀·한글에서 복사한 그대로 붙여넣으면 됩니다
- 학생 한 명씩 지우기

## 1단계에서 선생님이 직접 하셔야 하는 설정

컴퓨터 지식은 필요 없습니다. 아래 순서대로 눌러 주시면 됩니다.
화면의 메뉴 이름은 한국어와 영어를 같이 적어 두었습니다. Firebase 콘솔은
오른쪽 위에서 언어를 한국어로 바꿀 수 있습니다.

### A. Firebase 프로젝트 만들기

1. <https://console.firebase.google.com> 에 학교 구글 계정으로 로그인합니다.
2. **프로젝트 만들기(Create a project)** 를 누릅니다.
3. 프로젝트 이름을 적습니다. (예: `class-feedback`) 이름은 나중에 바꿀 수 있지만,
   그 아래 자동으로 만들어지는 **프로젝트 ID**는 나중에 못 바꾸니 그대로 두셔도 됩니다.
4. 약관에 동의하고 **계속(Continue)** 을 누릅니다.
5. **Google 애널리틱스(Google Analytics)** 는 **사용하지 않음**으로 두셔도 됩니다.
   이 프로그램에는 필요 없습니다.
6. **프로젝트 만들기(Create project)** 를 누르고 끝날 때까지 기다립니다.

### B. 웹 앱 등록하고 설정값 받기

1. 프로젝트 첫 화면 가운데에 있는 **웹(`</>`)** 아이콘을 누릅니다.
   (이미 앱을 만든 적이 있다면 **앱 추가(Add app)** → 웹)
2. 앱 닉네임을 적습니다. (예: `발표 평가`) 선생님만 보는 이름입니다.
   "Firebase 호스팅(Firebase Hosting)" 체크는 **하지 않습니다.** (배포는 Vercel로 합니다.)
3. **앱 등록(Register app)** 을 누릅니다.
4. 다음 화면에 `const firebaseConfig = { ... }` 라는 글상자가 나옵니다.
   여기 있는 값들을 **메모장에 복사해 두세요.** 뒤에서 씁니다.
   나중에 다시 보려면 **⚙ 프로젝트 설정(Project settings) → 내 앱(Your apps)** 에 있습니다.

이 프로그램에서 쓰는 값은 네 가지입니다.

| 메모해 둘 값 | 환경 변수 이름 |
| --- | --- |
| `apiKey` | `VITE_FIREBASE_API_KEY` |
| `authDomain` | `VITE_FIREBASE_AUTH_DOMAIN` |
| `projectId` | `VITE_FIREBASE_PROJECT_ID` |
| `appId` | `VITE_FIREBASE_APP_ID` |

> 이 값들은 비밀번호가 아닙니다. 웹 주소처럼 누구나 볼 수 있는 값이고,
> 실제 보안은 다음 단계에서 만들 **보안 규칙**이 맡습니다.

### C. Firestore 데이터베이스 만들기 (지역이 중요합니다)

1. 왼쪽 메뉴에서 **빌드(Build) → Firestore Database** 를 누릅니다.
2. **데이터베이스 만들기(Create database)** 를 누릅니다.
3. **위치(Location)** 에서 **`asia-northeast3` (Seoul / 서울)** 을 고릅니다.
   **이 지역은 나중에 바꿀 수 없으니** 꼭 확인하고 넘어가 주세요.
4. 규칙은 **프로덕션 모드(Production mode / 잠금 모드)** 로 시작합니다.
   지금은 아무도 읽고 쓸 수 없는 상태가 맞습니다. 2단계에서 규칙을 넣습니다.
5. **만들기(Create)** 를 누릅니다.

### D. 로그인 방법 켜기

1. 왼쪽 메뉴에서 **빌드(Build) → Authentication** 을 누르고 **시작하기(Get started)** 를 누릅니다.
2. **로그인 방법(Sign-in method)** 탭으로 갑니다.
3. **Google** 을 고르고 **사용 설정(Enable)** 을 켠 뒤, 프로젝트 지원 이메일을 고르고 **저장(Save)**.
   → 선생님 로그인에 씁니다.
4. 다시 **새 제공업체 추가(Add new provider)** 에서 **익명(Anonymous)** 을 고르고
   **사용 설정(Enable)** 을 켠 뒤 **저장(Save)**.
   → 학생이 계정 없이 들어오게 하는 데 씁니다.

### E. Vercel에 올리기

1. <https://vercel.com> 에 **GitHub 계정으로** 로그인합니다.
2. **Add New… → Project** 를 누르고 이 저장소(`class-feedback`)를 고릅니다.
3. Framework Preset이 **Vite** 로 잡혔는지 확인합니다. 나머지는 그대로 둡니다.
4. **Environment Variables** 를 펼쳐서, B에서 메모해 둔 값 네 개를 위 표의
   환경 변수 이름으로 하나씩 넣습니다.
5. **Deploy** 를 누릅니다. 1~2분 뒤 `무엇무엇.vercel.app` 주소가 나옵니다.

### F. 그 주소를 Firebase에 등록하기 (이걸 빠뜨리면 로그인이 안 됩니다)

1. Firebase 콘솔 → **Authentication → 설정(Settings) → 승인된 도메인(Authorized domains)**
2. **도메인 추가(Add domain)** 를 누르고 E에서 받은 주소를 넣습니다.
   `https://` 없이 `무엇무엇.vercel.app` 만 넣으면 됩니다.

### G. 확인하기

1. Vercel 주소를 엽니다.
2. 세 줄이 모두 초록색 체크면 성공입니다.
   마지막 줄은 **Firebase 연결 시험하기** 버튼을 눌러야 초록색이 됩니다.
3. 빨간 줄이 있으면 화면에 무엇을 고쳐야 하는지 한국어로 나옵니다.
4. **학생 태블릿을 학교 네트워크에 연결해서 같은 주소가 열리는지** 꼭 확인해 주세요.
   학교 망에서 막히는 경우가 있어서, 다음 단계로 가기 전에 미리 알아야 합니다.

## 개발자용 메모

```bash
npm install
cp .env.example .env   # 값을 채운다
npm run dev            # 개발 서버
npm run build          # 타입 검사 + 빌드
npm run lint
npm test               # 명단 해석기 등 단위 테스트
npm run test:rules     # 보안 규칙 테스트 (Firestore 에뮬레이터)
```

### 에뮬레이터로 돌려 보기

진짜 Firebase를 건드리지 않고 내 컴퓨터에서 시험할 때:

```bash
npx firebase emulators:start --only firestore,auth --project demo-class-feedback
```

`.env.local` 에 `VITE_USE_EMULATOR=true` 를 넣고 `npm run dev` 하면 앱이 에뮬레이터에 붙습니다.
(`VITE_FIREBASE_*` 값은 아무 글자나 넣어도 됩니다.)

- 기술 구성: Vite + React + TypeScript, Firebase(Firestore + Authentication), Vercel 배포
- 서버 코드 없음. Cloud Functions와 Cloud Storage는 쓰지 않는다(Spark 무료 요금제).
- 색·글꼴·치수 같은 디자인 값은 `src/styles/tokens.css` 한 곳에만 둔다.
- 보안 규칙은 `firestore.rules`. 고치면 `npm run test:rules` 로 확인하고 콘솔에 다시 게시한다.
- 입장 코드는 헷갈리는 글자(0 O 1 I L S B Z 2 8)를 뺀 6자리. `src/lib/joinCode.ts`
- 학생은 `joinCodes/{코드}` 문서 하나만 읽어 학급을 찾는다. 학급 목록을 훑지 못하게 하려는 것.
- 학생은 `classes/{id}.currentActivityId` 를 보고 지금 할 활동을 찾는다. 활동 목록은 못 훑는다.
- 평가 문서 id 는 `{발표id}__{학생id}`. 한 학생이 한 발표에 하나만 쓰도록 강제한다.
- 학생이 명단에서 이름을 고르면 그 문서에 `claimedBy`(익명 uid)가 찍힌다. 남이 고른 이름은 못 뺏는다.
- 공개용 결과는 `classes/{반}/students/{학생}/records/{활동}` 에 둔다. 교사 브라우저가 계산해 쓰고,
  공개를 취소하면 지운다. 계산은 `src/lib/results.ts` (화면도 Firestore 도 모르는 순수 함수).
- 자기 평가인지는 평가 문서의 `kind` 가 아니라 "평가자가 그 발표의 발표자인가"로 판단한다.
  `kind` 는 학생 기기가 적어 보낸 값이라 믿지 않는다.
- 교사용 누적 기록은 `classes/{반}/ledger/{활동}` 요약만 읽는다. 평가를 다시 읽으면 학급 하나의
  누적 기록을 한 번 여는 데 수천 건의 읽기가 들어 무료 한도(하루 5만 건)를 금방 쓴다.
- 엑셀은 `write-excel-file` 로 브라우저에서 만든다. 라이브러리는 버튼을 누를 때만 불러온다.
  시트 내용은 `src/lib/export.ts` 의 순수 함수가 만든다.
- Firestore 가 돌려주는 시각은 숫자가 아니라 Timestamp 다. 정렬할 때는 `src/lib/time.ts` 의 `toMillis` 를 쓴다.
- **활동과 발표를 한 묶음(batch)으로 쓰면 안 된다.** 발표 규칙이 부모 활동 문서를 `get()` 으로
  읽는데, 같은 묶음 안에서 만든 활동은 아직 보이지 않아 거부된다. 활동을 먼저 쓰고 발표를 그다음에 쓴다.
- Firestore 색인을 따로 만들 필요가 없도록, `where` 와 `orderBy` 를 같이 쓰지 않는다.
- `.env` 는 커밋하지 않는다. 실제 값은 Vercel 환경 변수에도 같이 넣어야 한다.
- `vercel.json` 의 rewrites는 SPA 깊은 링크(새로고침)가 404가 되지 않게 한다.
